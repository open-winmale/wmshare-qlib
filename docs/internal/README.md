# Internal engineering records

**These are process documents, not user documentation.** They are kept in-tree for
traceability — design rationale, cost probes, upstream negotiation, milestone logs —
and they contain owner-facing authorisation language, internal release identifiers
and dated snapshots that will go stale.

If you are here to *use* `wmshare-qlib`, read instead:

- [../getting-started.md](../getting-started.md)
- [../data-model.md](../data-model.md)
- [../faq.md](../faq.md)

| File | What it is |
|---|---|
| `HISTORY.md` | Design history and milestone log (M3-lite → M7-lite → P1-x) |
| `optimization-roadmap.md` | Forward plan, probe log, cost research |
| `upstream-daily-basic-plan.md` | Design + implementation record for the upstream materialized valuation table |
| `upstream-requests.md` | Feature requests filed against wmshare |
| `benchmark-card.md` | Internal acceptance benchmark (demo, 10 names × 120 days) |
| `full-market-expansion-review.md` | Cost review for expanding beyond the sample group |
| `pr_package/` | Draft material for an upstream Qlib collector PR (not submitted) |

Nothing here is a support commitment. Dates, EC figures and version numbers in
these files describe the moment they were written.
